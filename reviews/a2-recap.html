Miss #1 — Comments that repeat the code (19 students)

Only 4 perfect scores on Problem 7 — the lowest of any problem. Let's fix that right now.

The difference between a caption and a comment

What most of us wrote:
for n in numbers:  # go through each number in the list
big_numbers.append(n)  # add n to the list

True. Useless. The code already says that — you just said it twice.
What the 4 perfect scores wrote:
big_numbers.append(n)  # keep this one — it passed the cutoff
return big_numbers    # hand back only the survivors

Same line of code. But now the comment tells you something the code can't: the intent.
The test: cover the code with your hand and read only your comment. If you can't tell why the line exists, it's a caption, not a comment.

The same function, both ways

Captions (true, but the code already says it): 
# this function finds big numbers
def find_big_numbers(numbers, cutoff):
    big_numbers = []                  # make an empty list
    for n in numbers:                 # loop over the numbers
        if n > cutoff:                # check if n is bigger than cutoff
            big_numbers.append(n)     # add n to the list
    return big_numbers                # return the list
Comments (what the code can't say — purpose, intent, contract): 
# Return only the values above a cutoff, e.g. flagging orders over $100.
def find_big_numbers(numbers, cutoff):
    big_numbers = []                  # survivors collect here as we filter
    for n in numbers:                 # examine every candidate exactly once
        if n > cutoff:                # strictly greater — ties do NOT pass
            big_numbers.append(n)     # keep it: this one made the cut
    return big_numbers                # hand the caller just the keepers
Notice: the good version answers questions you'd otherwise have to ask — what's this for? do ties count? what comes back? That strictly greater comment has prevented a thousand real-world bugs.

Miss #4 — The two arithmetic traps (4 students each)

Trap 1: 17 % 5 — "that's 17 percent of 5… so 0.85?"
Trap 2: -7 // 2 — "7 // 2 is 3, so -7 // 2 is -3… right?"
Trap 1: % has nothing to do with percent. It's the remainder: 17 = 3×5 + 2.

Trap 2: // doesn't chop toward zero — it floors: always toward −∞.
-7 / 2 = -3.5 → floor → -4. On the number line, -4 is below -3.5.
Credit where due: several of you predicted wrong, ran the cell, and wrote "this surprised me, here's what I learned" — and earned full credit, exactly as promised. That's the scientific method, and it stays full-credit forever.

Miss #5 — Finding one bug and declaring victory

Problem 6 had two bugs. Several of you found the swapped counters but missed the + 2 — or fixed the + 2 and left the counters swapped. And one fix passed the test anyway. That last one is tonight's best lesson.
The tool that finds both, every time: playing the computer. Let's do it together.

Playing the computer 🖥️

You are the CPU now. One column per variable, one row per step. No skipping, no vibes.

def count_evens_and_odds(numbers):
    evens = 0
    odds = 0
    for n in numbers:
        if n % 2 == 0:
            odds = odds + 1      # bug 1: wrong counter
        else:
            evens = evens + 2    # bug 2: wrong counter AND +2
    return evens, odds

print(count_evens_and_odds([1, 2, 3, 4, 5, 6]))  # want (3, 3)

The trap: a wrong fix that passes the test

One submitted fix repaired the +2 but left the counters swapped — evens counts odds, odds counts evens. It printed (3, 3). Test passed. Full marks?

Takeaway: a symmetric test can't see a swap. When your test data has a coincidence in it, break the symmetry — then trace. "It printed the right thing" and "it's correct" are different claims.
